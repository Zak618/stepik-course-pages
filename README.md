# Страницы курса на Stepik

## Циклы — локальный просмотр

Модуль 04, урок 02: **20 шагов** — восемь интерактивных объяснений,
десять задач на Go и два теста. Подготовлено локально, **не опубликовано**.
При переносе: 12 заданий по 10 баллов, всего 120.

```sh
node scripts/preview-loops.mjs
```

Открыть `http://localhost:8777/loops`. Нужны Node 18+ и `/usr/bin/go`.
Оставить сервер работающим на время просмотра. Другой порт задаётся через
`STEPIK_LOOPS_PORT`. Имена файлов: `go-mini-module-04-lesson-02-preview.html`
и `go-mini-module-04-lesson-02-step-01.html` — `...step-20.html`.

Билетный автомат сравнивает один `if` и повторение; механизм позволяет
перематывать выполнение; парковка показывает ошибку границы; батарея —
цикл с условием и забытое изменение. Сканер различает пустую строку,
ожидание и конец ввода. Сортировка показывает `continue`, поиск — `break`,
лимит результатов и разницу между проверенными и найденными записями.
Предметы сделаны CSS/SVG; нет внешних картинок, шрифтов или библиотек.
Движения конечные, отключаемые, учитывают reduced motion и отменяются
при переходе. Белая поверхность чтения не имеет фиксированной высоты.

Первые семь задач дают заготовку чтения/подготовки данных. Последние три
оставляют только `package main` и пустую `main`: импорты, ввод, проверку,
цикл и счётчики студент пишет сам. Подсказки и разбор закрыты по умолчанию.
134 входных набора доступны в свёрнутых локальных тестовых данных;
при публикации использовать только штатные примеры Stepik, без дублей
в условии. Срезы, `range`, собственные функции и преобразование числового
ввода не вводятся раньше соответствующих тем.

Локальный запуск использует отдельный `scripts/lib/loops-runner.go`:
проверка допустимого AST, компиляция настоящим Go, ограничение вывода,
времени, размера строки и общего числа итераций (4096). Сначала компилируется
исходник студента, затем версия с ограничителями — неиспользуемые переменные
по-прежнему дают ошибку Go. Произвольные импорты, файлы, сеть, директивы,
пользовательские функции и доступ к служебным именам запрещены.
Это ограниченный учебный runner, **не универсальная песочница Go**.
Сервер слушает только loopback, проверяет Host/Origin и служебный заголовок,
не читает ключи, отдаёт только HTML/JS/CSS из явного списка. Runner-ы
предыдущих уроков не менялись.

Проверка при работающем просмотре: `node scripts/check-loops.mjs`.
Проверяются решения настоящим Go, ограничения runner/API, все страницы
на ширинах 320–1440 px, интерактивные состояния, пустой ввод, границы,
черновики, раскрытие данных, навигация и отсутствие внешних запросов.

Подготовка Stepik: `node scripts/export-loops.mjs`, затем
`node scripts/check-loops-graders.mjs` и `node scripts/check-loops-layout.mjs`.
Экспорт хранится в игнорируемой `.local-publication/`. Нативный checker
учитывает нормализацию краевых пробелов самой платформой; локальный runner
проверяет исходный вывод строго. [Официальная реализация Stepik](https://github.com/StepicOrg/stepik-plugins/blob/master/stepic_plugins/quizzes/code/__init__.py)
передаёт checker-у уже нормализованный stdout, поэтому он не должен
отклонять правильные программы на строках с пробелами по краям.
`scripts/publish-loops.mjs` по умолчанию выполняет только read-only preflight;
`--apply` создаёт шаги исключительно в уроке 2706564 после проверки файлов
на GitHub Pages. Снимки и журнал позволяют продолжить подтверждённые записи
без повторных POST, чужое содержимое не перезаписывается.

Источники идей: [видимое состояние программы](https://worrydream.com/LearnableProgramming/),
[управляемое время и механизмы](https://ciechanow.ski/mechanical-watch/),
[пошаговый разбор алгоритмов](https://www.redblobgames.com/pathfinding/a-star/introduction.html),
[игровые модели](https://ncase.me/loopy/). Иллюстрации и код оригинальные,
содержание сверено с [Go Tour](https://go.dev/tour/flowcontrol/1)
и [спецификацией for](https://go.dev/ref/spec#For_statements).

## Условия и логика

Модуль 04, урок 01: **20 шагов** — девять предметных опытов,
десять задач на Go и один тест. Опубликован в

11 заданий по 10 баллов, всего 110. Остальные 12 уроков, структура,
название и видимость курса сохранены.

```sh
node /home/rolan/stepik/stepik-course-pages/scripts/preview-conditions.mjs
```

Открыть `http://localhost:8775/conditions`. Сервер нужно оставить работающим
на время просмотра. Нужны Node 18+ и `/usr/bin/go`.
Другой порт: `STEPIK_CONDITIONS_PORT=8776 node scripts/preview-conditions.mjs`.
Общий просмотр и отдельные страницы названы
`go-mini-module-04-lesson-01-preview.html` и `...step-01.html` — `...step-20.html`.
Меню шагов, режим телефона, отдельная страница, отключение анимаций,
черновики и отметки проверок работают локально. Ничего не отправляется в Stepik.

| Шаги | Объяснение и практика |
| --- | --- |
| 01–02 | Весы, шесть сравнений, режим строк, `=` против `==` |
| 03–04 | Железнодорожная стрелка, `if/else`, общий код после веток, область видимости |
| 05–06 | Термостат оранжереи, `else if`, границы 20/30, независимые `if` |
| 07–09 | Лампочки, `&&`, `||`, `!`, скобки, проход сигнала и короткое замыкание, задача и тест |
| 10–11 | Музейный лифт: `switch`, `case`, общий case для двух имён, `default`, отсутствие автоматического fallthrough |
| 12–13 | Перестановка порогов: `switch` без значения, первый истинный case |
| 14–15 | `Scan()` возвращает bool: текст, пустая строка, конец ввода |
| 16–18 | Точное равенство и `strings.Contains`, регистр, пробелы и пустой запрос |
| 19–20 | Find по одной записи: заголовок, режим и запрос; вложенные условия |

Теория открыта целиком и продолжает пройденные темы без повторного приветствия.
Числа в опытах не требуют нового способа ввода. В задачах про температуру
готовый шаблон связывает именованные входные строки с числовыми показаниями;
преобразование строки в число не вводится незаметно. Циклов, срезов и собственных
функций ещё нет. `Scan() == false` не объявлен доказательством ошибки или EOF:
разница объяснена, а упражнение гарантирует короткий корректный ввод.

Все предметы и анимации нарисованы в SVG/CSS без внешних картинок, шрифтов,
библиотек и трекеров. Белая поверхность чтения, крупный текст, насыщенные
цвета опытов. Сцены используют ширину контейнера, в режиме `?panel=scene`
доступна только сама сцена до 1024 px. Нет фиксированной высоты страницы
или скрытого обрезания документа. Анимации конечные, доступны повторно,
отменяются при переходе и учитывают reduced motion.

Отдельный loopback-сервер `scripts/preview-conditions.mjs` не читает ключи
и не отдаёт произвольные файлы. Проверяет Host/Origin, тип запроса и служебный
заголовок, ограничивает код/ввод/вывод и одновременные запуски.
`scripts/lib/conditions-runner.go` проверяет AST перед настоящей компиляцией:
только ограниченная main, скалярные выражения, if/switch, fmt, scanner и Contains.
Запрещены файлы, сеть, циклы, сторонние импорты, директивы и произвольные функции.
Есть лимиты выражений, глубины, вывода и времени; верхние границы строк
объединяются консервативно по веткам с учётом областей видимости.
Окружение очищено, процессам не передаются ключи. Это **не универсальная
песочница Go**. Старые серверы и runner-ы не менялись.

Проверка: `node scripts/check-conditions.mjs` при работающем просмотре.
Проверяются все 136 входных наборов решений настоящим Go, ошибочные шаблоны,
ограничения API, страницы на пяти ширинах 320–1440 px, все девять опытов,
пустые/неизвестные значения, черновики, навигация и отсутствие внешних запросов.
Артефакты проверки сохраняются во временной папке.

Все проверочные наборы открыты: 12–20 на задачу, суммарно 136.
В Stepik используется только штатный блок тестовых данных с парами ввода
и вывода. Дублирующие примеры, синие блоки и «точные записи» из условия
удалены: ученик раскрывает данные средствами Stepik.
Локальная кнопка «Подставить вход» переносит выбранный пример в редактор ввода.
При публикации `samples_count` равен всему количеству наборов: скрытых тестов нет.
На статическом хостинге запуск Go заменён ссылкой в соответствующую задачу
Stepik; даже Ctrl+Enter не вызывает API выполнения.

Подготовка: `node scripts/export-conditions.mjs`, затем проверка нативной
обёртки `node scripts/check-conditions-layout.mjs`.
`node scripts/publish-conditions.mjs` — read-only preflight;
`--apply` разрешает создание только этих 20 шагов с резервной копией,
журналом ID, проверкой всех файлов Pages и всех открытых примеров в API.
Флаг `--compact-examples` убирает только известный дублирующий раздел
из уже опубликованных задач; тесты, шаблоны, баллы и открытость не меняет.
`--format-text` допускает только оформление с сохранением всего текста,
встроенных страниц, исходников проверок и баллов. Нативные блоки кода имеют
компактные поля и отступы: Stepik удаляет CSS-перенос длинных слов.
Другие уроки, названия, структура и видимость курса должны остаться неизменными.
Отправки решений от имени ученика нет. После переноса
`node scripts/check-conditions-layout.mjs --published` проверяет фактический
очищенный HTML Stepik, а не первоначальную заготовку.

Для подачи изучены [Mechanical Watch](https://ciechanow.ski/mechanical-watch/)
— управление предметом с наблюдаемым состоянием — и
[Red Blob Games](https://www.redblobgames.com/pathfinding/a-star/introduction.html)
— связь действия с маршрутом. Заимствованы принципы подачи, не изображения
или исходники. Семантика сверена с [if](https://go.dev/ref/spec#If_statements),
[switch](https://go.dev/ref/spec#Switch_statements),
[логическими операциями](https://go.dev/ref/spec#Logical_operators),
[Contains](https://pkg.go.dev/strings#Contains) и
[Scanner](https://pkg.go.dev/bufio#Scanner).

Белая поверхность чтения, крупный рассказ, насыщенные цветные сцены.
Ночное небо и корабль — объясняющие метафоры, а не иллюстрация внутреннего
устройства компьютера. Вся обязательная теория открыта. Текст продолжает
предыдущий урок без повторного приветствия и не требует условий, циклов,
пользовательских функций или преобразования строки в число. Задачи предполагают
нужное число коротких корректных строк. Ограничение объяснено: результат Scan
и ошибки будут разбираться после условий. Опыты не изображают готовый поиск.

Анимации запускаются действиями, конечны и отменяются при смене шага;
учитывается reduced motion, есть переключатель «Без анимаций».
Ввод доступен с клавиатуры. Цветные знаки показывают всю фразу, включая пробелы;
её точное значение доступно в текстовом результате. Смена кода сбрасывает отметку успешной проверки;
черновики хранятся только в localStorage. Локальные ответы не отправляются в Stepik.

`scripts/preview-input.mjs` — отдельный loopback-сервер с allowlist файлов,
проверкой Host, Origin и служебного заголовка. Не читает `.env` или ключи.
`scripts/lib/input-runner.go` — отдельный ограниченный Go runner, построенный
на проверенной реализации предыдущего урока. Дополнительно разрешены только
`bufio.NewScanner(os.Stdin)`, `scanner.Scan()` и `scanner.Text()`. Ввод ограничен
4096 байтами, код/вывод/время также ограничены. Окружение очищено, сборка и запуск
идут во временных каталогах. Произвольные файлы, сеть, циклы, init и сторонние
пакеты не разрешены. Это не универсальная песочница. API закрывает stdin после
переданных данных; живое ожидание Enter показывает интерактивная модель порта.
На статическом хостинге выполнение Go отключено, внешние API не вызываются.
Вместо неработающих кнопок есть переход в соответствующую задачу Stepik;
запуск с клавиатуры тоже отключён. Встроенные опыты работают без сервера Go.

Убраны декоративные подписи над предметами. Спутник построен в одной системе
координат с симметричными солнечными панелями.
Сообщение от спутника движется по точкам самого SVG-луча, без отдельного масштаба
и смещения относительно начала координат. Конец луча совпадает с видимым приёмником.
`node scripts/check-input-beam.mjs` проверяет положение плашки на девяти участках
пути при ширине 320/640/1024 px и reduced motion: 112 проверок без ошибок.
Поезд заменён чтением строки: луч последовательно проходит цветные знаки до Enter;
пробелы остаются в query.
Маяк и письмо заменены двумя крупными областями query/saved с показом копирования
и последующего изменения только query. Опыты находятся в
`assets/go-mini-input-replacements.js`, их стили — `go-mini-input-wide.css`.
Во время анимации ввод заблокирован: показ и результат относятся к одной строке.

`node scripts/export-input.mjs` измеряет 180 состояний на пяти ширинах
и готовит игнорируемую `.local-publication/input.json`. В Stepik рассказ остаётся
нативным HTML, в iframe находятся только шесть опытов (`?panel=scene`).
Панели используют всю ширину урока до 1024 px, а не принудительные 420 px.
Широкая компоновка остаётся широкой; телефонная включается по ширине контейнера.
`go-mini-input-embed-v2.css` распределяет высоту между предметом и контролами:
пустые резервы внутри полей удалены, последний статус находится у нижней границы.
Проверяются ширина каждой сцены и скрытое обрезание её внутренних элементов.
Длина ввода ограничена полем; нативные задачи не ограничены учебным макетом.
Исходники задач генерируют разные входные наборы и сохраняют значимые пробелы;
проверяется настоящий вывод, а не заранее выбранный одинаковый ответ.
`node scripts/publish-input.mjs` — read-only preflight, `--apply` разрешает перенос
только в этот урок с проверкой владельца, готовности Pages, журнала ID,
сохранности пяти предыдущих уроков, структуры и публичности курса.
Не удаляет чужое содержимое, не отправляет решения учащихся и не повторяет POST
вслепую после неопределённого результата. Ключи и артефакты не публикуются.

Проверка при работающем просмотре: `node scripts/check-input.mjs`.

Проверяются решения на разных входах, ошибочные программы, границы API,
взаимодействия, сбросы, черновики, клавиатура, отмена анимаций, отдельные страницы
