# Страницы курса на Stepik

## Общие введения курсов

`course-intros.html` показывает первые страницы 38 публичных курсов.
`course-intro.html?course=300153` — отдельный интерактивный пример.
34 предметных варианта используют HTML/CSS/SVG без библиотек и внешних
запросов: сборка страницы, корзина, фильтр записей, типы, история Git,
контейнеры, двоичный поиск, обмен запросом, путешествие, станция и другие.
Это модели поведения, не компилятор, база данных или подключение к ИИ.
Движения конечны, учитывают reduced motion; у сцены одна главная кнопка
или один ползунок. Карта берётся из готовой универсальной страницы.

Исходный текст — `scripts/course-intro-copy.mjs`.
`node scripts/snapshot-course-intros.mjs` снимает исходное состояние;
`node scripts/build-course-intros.mjs` готовит публичные профили и локальный
план. Снимок, план, измеренные высоты и журнал остаются в игнорируемой
`.local-publication/intros-20261116/`, а не на GitHub Pages.

Просмотр: `STEPIK_PREVIEW_PORT=8793 node scripts/preview.mjs`,
затем `http://localhost:8793/course-intros.html`.
`node scripts/check-course-intros.mjs` проверяет 34 примера на пяти ширинах,
состояния, клавиатуру, завершение движения и отсутствие внешних запросов.
Для другого сервера задайте `STEPIK_INTRO_URL`.
Высоты вставок берутся из измерений, отдельно для каждого курса.

`node scripts/publish-course-intros.mjs` выполняет только предварительную
проверку. `--apply` меняет текст существующих вводных шагов и добавляет
недостающие бесплатные шаги. Перед записью сверяются все введения,
задания, баллы, настройки курсов и готовность файлов на Pages.
Журнал позволяет продолжить прерванную публикацию без повторного создания
шагов. `--verify` повторно проверяет результат.

добавляется только карта. В трёх пакетах сохраняется короткая навигация
по фактическим дочерним курсам. В первом уроке путешествия по Уралу

Публикация завершена: 181 обновление текста, 36 новых бесплатных шагов.

## Итоговый проект

Модуль 06, урок 01: **12 шагов**, пять интерактивных объяснений и семь задач Go.
Опубликован в [уроке Stepik](https://stepik.org/lesson/2706569/step/1?unit=2746584),
[страницы](https://zak618.github.io/stepik-course-pages/go-mini-module-06-lesson-01-preview.html).
Локальный запуск:

```sh
node scripts/preview-project.mjs
```

Открыть `http://localhost:8785/project`. Сервер оставляется включённым для просмотра.
Нужны Node 18+ и `/usr/bin/go`; другой порт — `STEPIK_PROJECT_PORT`.
Общий просмотр `go-mini-module-06-lesson-01-preview.html`, отдельные шаги
`go-mini-module-06-lesson-01-step-01.html` — `...step-12.html`.

Find собирается из каталога, поиска, проверки названия, цикла команд и добавления.
Пять сцен: рабочее приложение, отбор папок в отдельный срез, маршрут for/switch,
сохранение добавления между командами и проверочный разговор с ошибками и выходом.
Предметы, текст и движения оригинальные; одна главная кнопка в каждой сцене,
движения конечны, отменяются при переходе, учитывают reduced motion.
Белая поверхность чтения, крупный текст, нет фиксированной высоты страницы.
Браузерные сцены — модели поведения; редактор задач запускает настоящий Go.
Ограничения числа папок в отдельных опытах не относятся к задачам.

Новых тем языка нет. Используются один Scanner в main, switch/for/continue/return,
[]string, append/range, Contains/TrimSpace, функции, error/nil, errors.New и Err.
Нет файлов, сети, структур, карт или параметров-указателей. Каталог живёт только
во время запуска. Поиск чувствителен к регистру, добавление допускает повторы,
убираются только крайние пробелы нового названия и запроса.
Два последних задания — пустая main. Все **88 проверочных входов** открыты
в свёрнутом разделе; примеры не дублируются в тексте условия. Решения свёрнуты.
Семь заданий по 10 баллов, всего 70.

Новый loopback-сервер использует существующий `scripts/lib/errors-runner.go`
без расширения его разрешений. Прежние страницы и серверы не менялись.
Сервер проверяет Host/Origin/служебный заголовок, отдаёт только файлы урока,
не читает ключи, ограничивает ввод/код/вывод/время и параллелизм.
Это ограниченный учебный запуск, не универсальная песочница Go.
Проверка: `node scripts/check-project.mjs`; `--ui-only` пропускает запуск Go.
Проверяются открытые наборы, реальные действия, ошибки и выход, сохранение кода,
ширины 320/390/768/1360, отмена движения и запрет доступа к ключам/файловому API.
Последняя проверка: 271 проверка без ошибок, все 88 наборов решений выполнены
настоящим Go. Скриншоты: `/tmp/find-project-qa-BP5uGX`.
Текст всех 12 шагов переписан: разговорные объяснения, короткие предложения,

В опытах добавляется одна новая папка, затем можно начать заново; в Go-задачах
такого ограничения нет. Длинный ответ доступен целиком в диалоге.
Проверены 108 состояний вставок на ширинах 390, 640, 1024; запас до следующего

Все 12 шагов готовы: пять объяснений и семь Go-задач по 10 баллов.
Все 88 примеров открыты в штатных тестовых данных; остальные 12 уроков,

## Ошибки и проверка ввода

Модуль 05, урок 03. **22 шага:** восемь интерактивных лекций,
12 задач Go и два теста. [Stepik](https://stepik.org/lesson/2706568/step/1?unit=2746583),
[GitHub Pages](https://zak618.github.io/stepik-course-pages/go-mini-module-05-lesson-03-preview.html).
14 заданий по 10 баллов, всего 140; 148 открытых наборов в штатных примерах Stepik,
без повторения примеров в условии. Запуск:

```sh
node scripts/preview-errors.mjs
```

Просмотр: `http://localhost:8783/errors`. Сервер оставляется включённым для
локального просмотра; Node 18+ и `/usr/bin/go`, другой порт — `STEPIK_ERRORS_PORT`.
Старые уроки и runner-ы не меняются.

Сцены: щётка убирает пробелы по краям запроса; автомат возвращает число и ошибку;
лифт разделяет преобразование и допустимый диапазон; почта отличает пустую
строку от конца и сбоя чтения; лента заказов показывает return и continue;
мастерская различает сборку, panic и неверный ответ; пекарня возвращает собственную
ошибку; Find безопасно выбирает один из найденных результатов.
Одно главное действие, краткие движения по нажатию, крупные значения,
белая поверхность чтения, без растягивания сцены до высоты экрана.
Рассказ и разборы открыты целиком; примеры задач и решения свёрнуты.
Три последние задачи — без готовой программы, все 148 наборов доступны локально.

Темы: `strings.TrimSpace`, `strconv.Atoi`, два результата, `error` / `nil`,
проверка диапазона до индекса, `Scan` / `Err`, функции `(int, error)` и
`(string, error)`, `errors.New`. Без интерфейсов, своих типов ошибок, указателей,
перехвата panic, файлов и сети. Новые сигнатуры объясняются перед практикой.
Ноль и пустая строка могут быть успешными результатами, поэтому проверяется
ошибка. Число вне диапазона — не то же самое, что ошибка преобразования.

Выделенные `scripts/preview-errors.mjs` и `scripts/lib/errors-runner.go` сохраняют
ограничения предыдущего runner-а: проверка AST, компиляция авторского кода до
инструментирования, пределы строк/срезов/вывода/времени и общий бюджет вызовов.
Добавлены только два результата известных функций, тип error, Atoi, TrimSpace,
errors.New и Scanner.Err. Файлы и сеть недоступны; глобальные переменные,
рекурсия, произвольные импорты, методы, директивы и служебные имена запрещены.
Это ограниченный учебный запуск, не универсальная песочница.
Проверка: `node scripts/check-errors.mjs` — решения на всех наборах, границы
runner-а, поведение сцен, мобильная вёрстка, сохранение кода и отмена анимаций.

Основное объяснение открыто; дополнительные нюансы раскрываются отдельно.
В опыте Find ищем заметки про циклы. Одна кнопка запускает конечный проход
лупы по четырём цветным заметкам; совпадения собираются в папку результатов.
Запросы `цикл`, `функц` и `пицца` дают 2, 1 и 0 записей. Регистр не учитывается,
пробельный запрос просит уточнить тему. При изменении ввода старый поиск отменяется.

Анимации конечные, учитывают `prefers-reduced-motion`; действия доступны
с клавиатуры. Ввод экранируется. Ответы и прогресс Stepik не отправляются,
Go в браузере не запускается. В Stepik рассказ экспортируется нативным HTML,
а в iframe остаются только опыты: `?panel=scene|carry|rgb`.
У встроенной версии байты доступны в диалоге с листанием, шкафчики — группами
по четыре; в поиске все четыре заметки видны сразу. Коробки тоже листаются
группами по четыре; все восемь по-прежнему участвуют в подсчёте.
Результаты проверки ответов открываются в диалоге внутри опыта;
найденные заметки остаются в папке под поиском.
Полные страницы сохраняют все данные. Это ограничивает высоту окна без
обрезания документа или ответов. Размеры предметов и строк статуса стабильны:
ответ не раздвигает встроенное окно и не требует запаса на пустой экран.
Видимый заголовок зачётных вопросов — «Проверим знания»; оценка остаётся
в нативных настройках Stepik и не добавляется в заголовок.

Экспорт: `node scripts/export-information-v2.mjs`. План и измерения разных
ширин/состояний записываются в игнорируемую `.local-publication/information-v2.json`.
Загрузка: `node scripts/publish-information-v2.mjs --apply`; без `--apply`
выполняется только проверка доступа. Скрипт сохраняет ID всех десяти шагов,
проверяет точные файлы GitHub Pages, создаёт резервную копию, сохраняет
публичность и статус черновика курса. Другие уроки не меняются.

Четыре нативных задания Stepik (шаги 04, 05, 07 и 09) оцениваются
**по 10 баллов, суммарно 40**. Типы: число, одиночный выбор, число,
одиночный выбор. Локальные упражнения не начисляют баллы и не заменяют зачёт.
Нативные ответы и комментарии проверки сохранены в экспортёре.

Для загрузки нужен владелец курса WEB HACKER (647088271).
Текущее приложение использует **client_credentials**, а не authorization-code:
`node scripts/authorize-webhacker.mjs --client-credentials` получает доступ
по уже настроенной `.env.stepik`, проверяет ID пользователя и владельца курса.
Повторный переход по браузерной ссылке авторизации для этого приложения не нужен.
Проверенная сессия сохраняется отдельно в игнорируемую
`.env.stepik-webhacker-session`; чужая `.env.stepik-session` не заменяется.
Режим callback без флага оставлен только для отдельных приложений,
настроенных именно на authorization-code. Ключи в публикацию не входят.

Проверка: `node scripts/check-information-v2.mjs` с `playwright-core` и Chrome.
При внешней установке передай `PLAYWRIGHT_MODULE` — абсолютный путь к `index.mjs`.
Проверяются взаимодействия всех десяти сцен, кодировки, смена шагов во время
анимации и ширины 320, 390, 768 и 1280 px; снимки сохраняются во временный каталог.
`node scripts/check-information-v2-layout.mjs` дополнительно проверяет нативную
разметку с cross-origin iframe, расстояние до следующего абзаца, отсутствие
внутреннего скролла, диалоги и раскрытые состояния на шести ширинах 320–1024 px.
После загрузки флаг `--published` использует сохранённый ответ API Stepik,
включая его реальную очистку HTML/CSS, а не исходный экспорт.

Идеи подачи изучены на [Ciechanowski](https://ciechanow.ski/mechanical-watch/),
[Red Blob Games](https://www.redblobgames.com/pathfinding/a-star/introduction.html)
и [Sight & Light](https://ncase.me/sight-and-light/).
Тексты, код и рисунки урока созданы самостоятельно.

Основной рассказ на каждой странице открыт: постановка вопроса перед опытом,

на ширинах 320, 390, 768 и 1024 px, а не по всему длинному рассказу.
